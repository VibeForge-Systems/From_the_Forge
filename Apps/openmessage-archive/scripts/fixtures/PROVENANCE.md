# Clean-room provenance record

This file records, for each clean-room file added in Milestone 3, the
sources consulted, what was written from them, and who wrote it (M3 spec
section 20.5). Source IDs refer to the M3 design spec's Appendix A,
repeated below for the IDs used here.

**Status: the independent clean-room review is pending.** Until a reviewer
records it here, this file is the author's statement only.

## Trust anchors and their limits

- The generator's writer reproduces T1's published sample byte for byte
  (233 bytes, SHA-256 `33162f000e9abad2ba56ebfcec6ef4ef671eb68048de1b0fc3c6bf2178412d9f`).
  The sample is not committed.
- Oracle 2 (T5, black box) agrees with the structure of every non-exempt
  vector; the run is recorded in `docs/compatibility.md`.
- Our writer and our decoder come from the same reading of T1, so their
  agreement (the round-trip test) shows internal consistency only. Apple's
  own encoder has not been run; that needs a Mac.
